# Install or update the shared rules (instructions for Claude Code)

Follow these steps when she says "install my rules", "update my rules" or the older "update my house rules". She is on Windows. `~` means `C:\Users\<name>`. Speak plainly (Background, Issue, Resolution).

**Tell her up front:** "I will ask your permission several times to copy files into your `.claude` folder. Please say Yes each time."

1. **Get the latest kit.** Detect which shell you have. In PowerShell: if `~\claude-house-rules` exists run `git -C "$HOME\claude-house-rules" pull`, otherwise run `git clone https://github.com/Reuven93/claude-house-rules "$HOME\claude-house-rules"`. In Git Bash: the same commands with `~/claude-house-rules`. If the pull fails because files in that folder were edited, show her which files, keep her edits out of the way with `git -C <folder> stash` (tell her they are saved there), and pull again. The repo is public: no GitHub account or sign-in is needed. If git is missing, install it for her with `winget install --id Git.Git -e` (ask her OK first), then continue.
2. **Compare** each kit file with the installed one (a missing file counts as "new"):

   | Kit file | Installed at |
   |---|---|
   | `shared-rules.md` | `~\.claude\shared-rules.md` (replaced on update, with backup) |
   | `hooks\*.sh` (4 files: `prompt-gate.sh`, `model-guard.sh`, `plan-gate.sh`, `reply-check.sh`; not `hooks\tests\`) | `~\.claude\hooks\` (the automatic checks) |
   | `skills\handover\SKILL.md`, `skills\handover\TEMPLATE.md` | `~\.claude\skills\handover\` |
   | `skills\rules-check\SKILL.md` | `~\.claude\skills\rules-check\` |
   | `agents\helper-*.md` (6 files) | `~\.claude\agents\` |
   | `settings.json` | `~\.claude\settings.json` (merge, step 5) |

   `~\.claude\CLAUDE.md` is HERS and is not a kit file: it is handled in step 5. Do not touch other files in `~\.claude`, and do not delete anything there.
3. **Show her a short plain list** of what will change: for each file "new", "changed" (one line on what differs, e.g. the new shared-rules version) or "same". Also say what will happen to her `CLAUDE.md` (see step 5). If nothing differs and her `CLAUDE.md` already has the `@shared-rules.md` line (and no old `house-rules.md`), say "You are up to date" and stop.
4. **Wait for her OK.** Do nothing before it.
5. **Apply.**
   - **Kit files:** for each new or changed file, if an installed file exists, first copy it into `~\.claude\shared-rules-backup\<date-time>\`, keeping its sub-folder (e.g. `agents\helper-light.md`, `hooks\plan-gate.sh`). Never leave backups inside `agents\` or `skills\`: Claude Code may load them as extra helpers or skills. Create folders if needed; then copy the kit file over it.
   - **Her `CLAUDE.md`:** it must contain the line `@shared-rules.md` at the very top and a `## My own rules` section. If she has no `CLAUDE.md`, create one with `@shared-rules.md` followed by the content of the kit's `my-rules-template.md`. **One-time move (rules 26/11/2026b):** the Windows and helper-name rules left the shared rules file; if her `## My own rules` section has no `### My machine (Windows PC)` heading, append the `###` blocks from `my-rules-template.md` to the end of that section (backup first, show her the addition, change nothing else she wrote). First install with an existing `CLAUDE.md`: show it to her, and with her OK move its content under `## My own rules` (copy it into the same backup folder first). **One-time rename (house rules became shared rules):** if her `CLAUDE.md` has the line `@house-rules.md`, replace it with `@shared-rules.md` (backup first), and move the old `~\.claude\house-rules.md` into the backup folder (do not leave it in `~\.claude`). On later updates only add the `@shared-rules.md` line if it is missing; never touch the `## My own rules` section or anything she wrote.
   - **`settings.json`:** read her installed file (create `{}` if missing), set only `"model": "opusplan"` and the three `env` keys (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, `CLAUDE_CODE_SUBAGENT_MODEL` = `"sonnet"`, which makes helpers that don't name a model run on Sonnet, not Opus; helpers that name their own model keep it) from the kit's `settings.json`, also merge the kit's `hooks` block: for each kit entry (event + matcher + command), add it only if her file has no entry with the same command under that event; never remove or change her own hooks or other entries; keep every other key (including other `env` keys) exactly as is, and back it up into the same backup folder first. Valid JSON only.
6. **Check:** run `claude --version`; the helper limit setting needs 2.1.217 or later, so if it is older tell her to update Claude Code. List the installed files and confirm `settings.json` still parses. Then run each of the four hooks once through bash with a sample JSON to confirm it runs (exit 0), for example in Git Bash: `echo '{"session_id":"install-check","hook_event_name":"UserPromptSubmit","prompt":"hello"}' | bash "$HOME/.claude/hooks/prompt-gate.sh"; echo $?` (use `hook_event_name` `PreToolUse` with `"tool_name":"Agent"` for `model-guard.sh`, `PostToolUse` with `"tool_name":"Edit"` for `reply-check.sh`, `PreToolUse` with `"tool_name":"Bash"` for `plan-gate.sh`). If one does not exit 0, tell her which. Report in 1-3 lines what was installed, the version line from `shared-rules.md`, and that the automatic checks are on (they check her rules for her, for example plan before edits and the stronger model only with her OK).
7. **Tell her:** "Start a new chat so the new rules load." Then stop.
